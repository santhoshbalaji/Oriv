# Browser profiles

Profiles separate tabs, website cookies/storage, preferences, bookmarks, history and downloads. Personal retains its existing paths and default WebKit store; additional profiles use stable UUID directories and named WebKit stores. Existing saved data belonging to removed features remains at those paths without being opened as an active service.

On Mac, use Profiles → Manage Profiles to create, rename, color, switch, archive or restore. Switching uses the current window and preserves live page/form state. Page operations and open dialogs block switching until finished. An inactive profile cannot present website dialogs or new popups. Archive is recoverable and refuses unfinished downloads or edited forms; Personal and the active profile cannot be archived.

On iPhone, Settings → Choose profile creates/selects local browser profiles. The older mobile profile-name list is read for compatibility, retaining its UUID and website storage. Controllers for unselected profiles are created only when needed for browsing or enabled continuity; sync leaves their WebViews inactive. Switching works offline without an account. Optional [browser continuity](browser-continuity.md) syncs profile identity, name, color and symbol, plus the profile’s regular browser records and preferences. Active selection and archive state remain device-local; a remote rename never switches the visible profile or joins website stores. Independently created names do not imply the same identity.

External links default to a separate profile-less private window or iPhone tab group, with non-persistent website data and no profile data. The “Opened privately” banner can move only the current HTTP(S) URL to a chosen regular profile; it copies no cookies or form state. Settings → Browsing can restore regular-profile external opening. See [browser continuity](browser-continuity.md#links-from-other-apps) for the controls and lifetime.

On Mac, File → New Private Window opens a dedicated private session, separate from profile tabs, the external-private window and any other private windows. File → New Private Tab puts a tab in the current window. New private windows and external-private contexts copy the active profile’s blocker mode, search engine, privacy-layer switches and appearance at creation. Site exceptions, site rules, cookies and history stay in the originating profile.

One-shot **Open on [Device]** requests use the same profile UUID matching as remote tabs. Missing profiles wait for synced metadata; archived profiles stay archived until explicitly restored, and requests expire after seven days. Each delivered page opens as a new regular tab in its matching profile.

Website data follows the [private tab isolation setting](privacy.md#private-tab-isolation). Private permission exceptions belong to the private session and disappear after its last private tab closes. macOS/iOS permissions and system Password AutoFill remain OS-level services. Browser profiles do not create separate operating-system accounts.

Tests cover browser records and recovery, separate WebKit cookies/stores, private-store identity, preserved forms, bookmark persistence and archive/restore. Physical-device, VoiceOver and real-provider acceptance remain separate from local regression tests.

Use **Delete Profile…** from Manage Profiles on Mac or the profile’s touch-and-hold menu on iPhone. You can delete an inactive additional profile, including an archived one. The original Personal profile uses the legacy default website store and is retained. Deletion removes the profile’s tabs, history, bookmarks, preferences, favicons, and named WebKit data store. Files you saved to Downloads or Files remain yours. Deletion follows the profile to other devices through [Browser continuity](browser-continuity.md#what-moves-between-devices).
