# Browser continuity

Optional browser continuity shares regular-browser metadata between Mac and iPhone, independently of the removed Workspace product. The [implementation plan](browser-implementation-plan.md) records remaining correctness, delivery and recovery work. This document describes reusable configuration and test boundaries; it does not record personal account or device history.

## What moves between devices

| Data | Behavior |
| --- | --- |
| Bookmarks | Additions merge; known deletions propagate; explicit Undo restores a bookmark. Independently saved copies of the same URL appear once. |
| History | The newest 500 distinct regular pages per profile, matching the existing browser limit. Clearing history propagates a time-range marker, including older visits from an offline device. Removed/evicted records retain identifiers as tombstones but discard their URL/title payloads. |
| Profiles | Stable UUID, name, color and symbol. Profiles created independently with the same name retain separate identities and get a name suffix. Website stores are never joined by name. |
| Regular tabs | A device-owned list of URL, title, pin state and order in Library → Other devices. Closing a tab updates that device’s list. Opening a remote page creates a new regular tab in its matching profile. Local live tabs and edited forms are never replaced by a remote session. |
| Preferences | Per-profile appearance, search engine, restore-tabs choice, default zoom, blocking mode, regular-site exceptions and regular-site rules. OS device permissions remain local. |
| Open on another device | An explicit page-menu action sends one regular HTTP(S) page to a selected known device. It creates a new regular tab in the matching profile and leaves all existing tabs intact. |
| Handoff | Publishes the selected regular HTTP(S) page while foregrounded, after account verification and with sync/Handoff enabled. Receives a validated URL and profile identity and opens a new tab. Private pages withdraw the activity. |

Website cookies/login sessions, private tabs, form values, downloads, selected profile, profile archive state, private site exceptions/rules and OS grants remain on the device. Passwords/passkeys use the platform’s Passwords/Keychain facilities; this implementation does not copy credentials. Local browsing works without any iCloud or developer account.

Archiving a profile hides it on the current device and withdraws that device’s tab list. Its synced bookmarks/history remain associated with the profile; another device may continue using it. Restore the profile before opening one of its remote tabs on the device where it is archived.

Deleting an additional profile writes a permanent profile tombstone using the existing encrypted record format. The same sync cycle replaces its known synced data with payload-free tombstones, including open requests. Older offline edits are redacted when they arrive. The shared zone still holds other profiles and device records. Updated devices remove their local copies after receiving the tombstone. An offline or paused device applies it after it reconnects and syncs. Upgrade every synced device before relying on profile deletion across devices.

## Controls and delivery

Mac: Settings → Continuity. iPhone: Settings → Mac & iPhone → Continuity. Both expose opt-in, status, last successful sync, Sync now, a device name and Handoff. Library → Other devices shows last-seen timestamps. Pausing sync keeps existing local and cloud copies; resuming merges locally journaled edits. A cloud request already submitted when paused may finish, but subsequent upload batches are cancelled.

The coordinator debounces local changes for two seconds and catches up immediately on foreground return. Silent CloudKit pushes bypass that debounce and use the same incremental zone fetch. Bursts before a fetch coalesce into one cycle; pushes during a cycle request one immediate follow-up. Open on another device remains an immediate send. Other-device lists are snapshots, not live remote control. The device heartbeat changes at most every five minutes. Device-removal/cloud-reset UI remains later work.

Foreground reconciliation fetches only zone changes since the process-local server token. When there are no incoming changes, dirty local records, pending deliveries or due heartbeat/expiry maintenance, it returns without capturing sessions, merging, writing, applying or uploading records. Local session notifications compare only their profile's changed snapshot fields; selection alone does not dirty shared tabs. Observable preferences are tracked separately, so tab selection does not re-encode site rules. Uploads contain only dirty keys, including deletion tombstones; edits made during an upload remain dirty until their exact revision is acknowledged.

The initial rollout has an explicit 100,000-record / 100 MB local safety ceiling. Tombstones are retained to protect offline replicas; exceeding a ceiling pauses sync rather than silently dropping deletion information. A coordinated tombstone-compaction policy is still needed for long-lived high-volume libraries. The 500-history-page limit bounds retained page payloads, not the tombstone count.

## Silent push and polling fallback

After explicit continuity opt-in, the app registers with APNs without requesting user notification permission. The private `BrowserContinuityV1` zone has one stable `CKRecordZoneSubscription` (`BrowserContinuityV1.silent.v1`) with `shouldSendContentAvailable = true`. It has no alert, badge, sound or desired record keys. Pushes contain only CloudKit routing metadata, never browsing URLs, titles, page bodies or encrypted record bodies. Neither APNs tokens nor record contents are logged or uploaded by the app's notification handler.

A hashed preferences key scopes the saved subscription ID to app, container, environment, account and zone. A new transport verifies a remembered subscription once rather than saving it again. Zone reset, account change, a missing/unknown subscription or a subscription error invalidates this cache. A missing subscription is recreated; a reset previously used cloud zone still pauses sync under the existing data-recovery rules. Push setup errors never prevent normal polling or local browsing. Registration failures retry on a later foreground transition. Ordinary unsigned/test builds do not require working push; Mac background-UI tests suppress APNs registration. Legacy local-only Mac Debug/Release entitlements omit APNs so their ad-hoc signing remains independent of provisioning; the signed continuity configurations retain the push entitlement.

Foreground polling defaults to **30 seconds**. It slows to **5 minutes** only when this process has successfully registered with APNs, saved/verified its zone subscription, and received a matching push whose subscription owner matches its verified bound account within the last **24 hours**. A push with no owner identity still triggers a fetch but cannot establish health. Registration alone does not establish delivery. Health evidence is deliberately process-local, so a relaunch starts conservatively. Registration failure, subscription error, account invalidation, or expiration of that push evidence restores the 30-second interval automatically, including a timer wake at the freshness boundary. A poll that discovers a new remote revision without a push since the previous fetch also clears delivery evidence and forces subscription verification; initial downloads and unchanged/self-upload echoes do not count as missed pushes. A later successful subscription check and fresh push can restore the slower interval.

Handlers accept only the configured container, private database, continuity zone and subscription ID. The iOS delegate supports silent background launch before any scene appears. Each notification's fetch completion is called exactly once with new-data, no-data or failure, with a **25-second deadline** inside Apple's 30-second opportunity. A background timeout cancels further transport work and rejects late responses through the account/generation guard. Background delivery does not raise the Mac window. If continuity deletes the selected profile, Oriv falls back to Personal. Continuity opt-out ignores pushes and leaves local browsing available. APNs may throttle/coalesce background pushes, and force-quit delivery is not promised; foreground catch-up and polling remain necessary.

## Open on another device

The Mac page menu offers **Open on iPhone** and the iPhone page menu offers **Open on Mac**, using the synced destination name for a single device. With several other devices, a submenu lists each by its synced name. The action is hidden until sync is enabled, the bound account is verified, another device is known, and the current tab is a regular HTTP(S) page. The sender briefly shows “Sent to [device]”; the receiver shows “Opened from [source]”. Existing regular-tab sync is unchanged.

Each send writes an `openRequest` continuity payload under `open.<request UUID>` using the existing `BrowserRecordV1` record type and encrypted `body` field. There are no new CloudKit types or fields. The encrypted payload contains the request UUID, target and source device UUIDs, source device name, validated HTTP(S) URL, title, profile UUID and creation date. Sending requests an immediate foreground sync. A silent zone push requests an immediate receiver fetch, including an iOS background opportunity when the OS allows it. Delivery while suspended or quit is subject to Apple scheduling; instant delivery is not guaranteed.

Only the target device applies a request, after account verification. A matching synced profile is imported using the same identity rules as Other Devices. An archived profile must be restored before its request can open; a missing identity waits for its profile metadata. Requests never fall back to a different profile. Unhandled requests expire after seven days and are tombstoned. Receipt creates a new regular tab using the destination's website store, never the sender's cookies or form state.

Before acknowledging a request, the receiver atomically saves its request receipt together with the new tab in the profile's session snapshot. Replaying an interrupted incoming journal checks that durable receipt, including after the delivered tab is closed or the app relaunches. It then writes a normal replica tombstone. A failed session write leaves the request available for retry. Tombstones retain deletion identity and discard the page payload.

**Upgrade both devices together for this release.** Oriv 0.6.0 uses a closed synthesized payload decoder and rejects the new record kind, pausing its sync. Updated CloudKit readers inspect the encrypted body and skip unknown future kinds, including unknown tombstones, without treating them as deletions. Malformed known records still fail the batch. This forward tolerance cannot change an older installed decoder.

## Links from other apps

On both platforms, **Open Links from Other Apps Privately** defaults to on in Settings → Browsing (Mac: Settings → General → Browsing). Incoming HTTP(S) links open signed out in a profile-less, memory-only private context. Repeated links add tabs to one external-private Mac window or iPhone private tab group. At creation they copy the active profile’s blocker mode, search engine, privacy-layer switches and appearance. They use independent website data and never enter continuity. Links clicked inside Oriv retain their existing behavior. Turning the setting off restores opening external links as new regular tabs in the last regular profile.

The private banner says “Opened privately”, adding a source app name only when the active Mac URL Apple event reliably identifies its sender. iPhone does not infer a source application. Its profile picker starts at the last regular profile. **Move to [Profile]** opens the selected private tab's current HTTP(S) URL as a new regular tab in that profile, focuses it, then closes the private tab (and an empty external-private Mac window). Only the URL crosses this boundary: the destination uses its own sign-ins, with no private cookies, form data or session state copied. Non-HTTP(S) pages have no Move action. **Keep Private** dismisses the banner and leaves the page private. The iPhone page menu can return to the last regular profile or reopen a retained external-private group.

The banner uses native pickers and buttons, semantic theme tokens and solid surfaces, respects the app's Reduce Motion/Transparency settings, and provides keyboard/VoiceOver labels and 44-point iPhone controls.

## Merge, storage and account boundaries

`BrowserCore/BrowserContinuityRecords.swift` defines an allowlist of metadata payloads and validated record identities. A persisted logical counter and writer UUID give deterministic conflict resolution. Concurrent edits to different records merge independently; the same record resolves by counter, then deletion, then writer identity. A profile deletion takes precedence over all edits to that profile. A newly joining device’s initial metadata/preferences yield to records already in iCloud, so its defaults do not overwrite established settings.

`continuity/replica.json` is atomically written with owner-only file access and iOS file protection. Encoding and atomic writes use an ordered worker queue. A changed reconciliation writes the replica at most once; incoming application waits for that journal's durability before changing sessions. The on-disk pending marker may remain set until the next write or lifecycle flush; replay is idempotent, including request receipts. Recovery applies that journal before interpreting a missing local bookmark as deletion. Future/corrupt stores stop sync without rewriting the original file. Ordinary session application changes bookmarks/history/preferences without replacing tabs or WebKit website stores. Session saves compare the persisted snapshot before queuing compact JSON encoding and atomic writes on their own ordered worker. The first changed save per store launch preserves a valid primary backup; later saves do not rotate it. Privacy erasure still removes the backup, including on an otherwise unchanged save. Backgrounding and termination drain queued writes. History deletion markers are also journaled before erasing the session, so a crash during the debounce cannot restore deleted cloud history. Explicit setting changes, sends, privacy transactions and lifecycle flushes are separate from the per-cycle write budget. Privacy erasure, incoming application and open-request receipts remain synchronous durability barriers while their encoding and file work run on the worker. Explicit open requests append a new tab through the separate receipt transaction above.

`BrowserEngine/ContinuityCloudTransport.swift` is the sole CloudKit client, instantiated only after explicit opt-in. It uses a private custom zone (`BrowserContinuityV1`), records of type `BrowserRecordV1`, and an encrypted `body` field. Record names contain UUIDs/category names, not URL/title text. Fetches are paginated and validated before accepting the batch. Uploads use change-tag checks and inspect individual results; conflicts are merged and retried. Partial failures preserve the local journal and do not mark sync successful.

The replica binds to its first iCloud user-record identity. Account identity is checked once at the start of each cycle. `CKAccountChanged` synchronously invalidates the active generation on the main actor, withdraws Handoff, cancels subsequent upload batches and restarts verification. Generation checks after network awaits reject an invalidated response before import or further upload. The zone is verified once per transport lifetime and checked again after a zone-not-found error. An account mismatch pauses uploads; it never automatically moves old account data into a new account. A missing/reset previously used cloud zone also pauses rather than repopulating it automatically. The user must return to the original account; switching accounts or recreating a reset store needs an explicit future recovery flow. CloudKit token cache is process-local, so relaunch performs a complete zone fetch. Dirty keys are retained in the local version-1 replica; older replicas without that optional journal retry all their records once. CloudKit record types and fields are unchanged. APNs signing entitlements and the iOS remote-notification background mode are added for silent delivery. Cloud-service quota/rate-limit behavior still needs acceptance testing with a real account.

Handoff uses `com.santhoshbalaji.oriv.dev.browsing`, declared in both app Info plists, with no Search/public indexing eligibility. The payload includes only validated page/profile metadata. Handoff availability requires compatible Apple-signed apps and device settings; the simulator tests validate payloads and routing logic, not physical Handoff discovery.

Apple references: [encrypted CloudKit fields](https://github.com/apple/sample-cloudkit-encryption), [record-zone changes](https://developer.apple.com/documentation/cloudkit/ckdatabase/recordzonechanges(inzonewith:since:desiredkeys:resultslimit:)), [Handoff implementation](https://developer.apple.com/documentation/foundation/implementing-handoff-in-your-app).

## Build configuration

`project.yml` is the source of truth. Committed `DEVELOPMENT_TEAM` values are blank; select your own team only through a local override. See [local signing setup](../CONTRIBUTING.md#local-signing-setup) for unsigned Debug builds and signed-build commands.

Generation runs `scripts/normalize-xcode-capabilities.py` to repair the nested-capability serialization bug in XcodeGen 2.46. It preserves `project.yml` values as actual project dictionaries and is a no-op for generators that already write the correct form. See [upstream issue](https://github.com/yonaskolb/XcodeGen/issues/1637).

- `ContinuityDevelopment`, through `OrivContinuityMac` and `OrivContinuityMobile`, declares the Development CloudKit environment and `iCloud.com.santhoshbalaji.oriv.browser.dev`.
- The Mac development bundle is `com.santhoshbalaji.oriv.mac.dev`, product `Oriv-Continuity-Dev`. The iPhone development bundle is `com.santhoshbalaji.oriv.ios.dev`, product `Oriv-Mobile-Dev`.
- The APNs environment comes from `ORIV_PUSH_ENVIRONMENT`: development for Debug/BrowserDevelopment/ContinuityDevelopment; production for Release/ContinuityRelease. All entitlement variants use the platform-specific APNs key. iOS declares `UIBackgroundModes = [remote-notification]`; `project.yml` generates both Info plists and the checked-in Xcode project.
- Ordinary Debug builds have no iCloud container configured. Their continuity controls explain why enabling sync is unavailable.
- `ContinuityRelease`, through `OrivReleaseMac` and `OrivReleaseMobile`, selects the separate Production CloudKit environment. The Mac bundle remains `local.personalbrowser.mac`; iPhone uses `com.santhoshbalaji.oriv.ios`. The release Handoff type is `com.santhoshbalaji.oriv.browsing`.
- Development and Production CloudKit data are separate even when they use the same container identifier. Its historical `.dev` suffix does not select the environment. Development replica files and test data are not copied automatically into Production. Sync remains opt-in.

Both continuity targets need the iCloud capability, the CloudKit service, an explicit container environment, and the container association for the contributor's team. Development entitlements include both container-identifier lists; Production entitlements omit the development-only list. The scope guard checks this allowlist. These capabilities do not restore Workspace app groups, Calendar, AI or extensions. Managed browser capabilities require their own approval; declaring an entitlement alone does not grant it.

CloudKit schema deployment is separate from local compilation and signing. Contributors must configure and verify their own container's schema and Production environment. See Apple's [container-schema deployment guidance](https://developer.apple.com/documentation/cloudkit/deploying-an-icloud-container-s-schema).

## Verification boundaries

Synthetic push tests cover subscription save/reuse/recreation, account/reset/error invalidation, silent configuration, burst/follow-up coalescing, bounded exactly-once completion, missing registration/entitlements and 30-second/5-minute health transitions. Other package and native tests cover a 5,002-record no-change cycle (one fetch/account check and zero captures, writes, applies or pushes), dirty-key upload/retry, writer ordering, once-per-launch backups, notification invalidation during fetch, pending delivery after profile restoration, immediate send, request validation/targeting/expiry, durable receipt replay, profile matching, unknown-kind tolerance, external-private routing/isolation/Move, convergence, joining-device defaults, offline deletion/Undo, history erasure and retention, tab order/ownership, profile name collisions, account binding, corrupt/future data and Handoff validation. Coordinator fixtures use an in-memory transport to check opt-in, private-tab exclusion, two-device merge, account-switch rejection, failures, journal recovery and preservation of local tabs/private overrides. These tests do not establish real CloudKit delivery or physical Handoff discovery.

Debug Simulator builds accept repeated `--oriv-external-url` launch arguments to exercise the same external-link router and private banner without changing the Simulator default browser. This checks routing and UI, separately from OS default-browser delivery.

Use synthetic pages and dedicated test accounts when validating signed builds on compatible devices:

1. Verify bookmarks, deletion/Undo, preferences, profiles, regular-tab order/pinning and Handoff in both directions without replacing edited/private tabs.
2. Disconnect a device, edit both, clear history on one, reconnect and relaunch; confirm convergence and absence of deleted URL payloads.
3. Exercise account sign-out/switch, quota exhaustion, rate limiting, interrupted batches, encrypted-key reset and zone removal. Confirm visible failure with local data retained and no cross-account upload.
4. Verify Handoff withdrawal for private pages, disabled sync, backgrounding and account errors; measure foreground cost with a representative library.
5. Verify Development/Production separation, warm/cold Handoff, upgrade/data preservation and rollback before considering a production installation. The production release hold remains in place until the implementation-plan gates pass.

## Seamless continuity requirement and remaining implementation

After an explicit initial opt-in, ordinary browsing should not require Sync now, reopening both apps, or visiting sync settings. Background delivery is subject to Apple's scheduling and cannot be guaranteed instantly while an app is suspended or force-quit.

The current coordinator debounces local changes for two seconds, handles silent zone pushes immediately, and polls while foregrounded under the health policy above. Network-reconnection triggers, durable server tokens, outgoing background completion and server-directed retry/backoff remain unimplemented. The local replica and merge journal preserve offline edits; physical push delivery and energy/latency targets still need device acceptance.

Pending work:

1. Resolve the Handoff activity type from the build configuration and defer valid cold-start Handoff until account verification completes. Runtime currently defaults to the development type, which differs from the release declaration.
2. Verify silent push on both signed physical apps; add a bounded outgoing-write opportunity when backgrounding and automatic catch-up on reconnection. The implemented push handlers are a bounded transport increment, not the planned CKSyncEngine scheduling migration.
3. Persist incremental cloud sync state across relaunches; respect server retry delays, quota/network failures and interrupted batches without busy retry loops.
4. Add clear pending/offline/action-required statuses and safe user-controlled recovery for account changes, cloud resets and unreadable local replicas. Include old-device removal and stale-tab cleanup.
5. Reduce full-store scans/writes, compact deletion records without reviving offline deletions, and measure latency, battery, CPU and large-library cost. History currently retains 500 distinct pages per profile; retention beyond that is a separate scope decision.
6. Complete the synthetic-data acceptance matrix above before a production installation.
