# Oriv 0.5.0 — design and native Passwords guidance

Verified on 25 October 2026, macOS 27.0.1 / Xcode 27. Build 5 retains the `local.personalbrowser.mac` bundle identifier and existing data locations.

## Changes

- A shared Mulberry/Paper/Mist design system, system serif headings and a restrained woven-line motif connect browsing to saved context. The accepted kolam app icon is retained.
- Browser sidebar, start page, Workspace, capture/note/action editors, history/downloads, ad-block controls and Settings share the new hierarchy. Native glass is used for navigation and controls; reading surfaces remain opaque.
- New-tab continuation uses real saved items and next actions. Private new tabs do not show normal bookmarks/history/workspace suggestions.
- Password AutoFill guidance is available from the browser's key button, Library menu and Settings. The native WebKit field menu remains intact; no credentials are bridged through JavaScript, imported or stored by Oriv.
- Dark native row-selection colors and selected site monograms were corrected after visual inspection.

See [design principles and inspirations](../design-system.md) and [Passwords setup, evidence and limits](../passwords.md).

## Remaining boundaries

- The verified password flow is user-invoked **Control-click a webpage field → AutoFill → Passwords…**. Authenticated insertion of an actual saved credential remains a manual acceptance check. Safari-style automatic per-site suggestion dropdowns, automatic password generation/saving and browser passkeys are not implemented by this release.
- Passwords provider setup and device authentication are required on the user's Mac. No additional Oriv entitlement is needed for the verified native field-menu flow. The separate browser passkey entitlement requires Apple's approval and appropriate provisioning; it is not permission to read the password vault.
- Minimum-width/compact-height interactive resizing could not be reliably exercised with the current native automation tool. Normal windows, sidebar collapse and both appearance modes were checked; this is not a completed compact-window audit.
- Full VoiceOver, Full Keyboard Access, Increase Contrast and Reduce Transparency acceptance remain outstanding. Native controls and adaptive colors are used, but this is not a claim of exhaustive Apple HIG/accessibility conformance or certification.
- WebKit/fullscreen/filtering logic was not changed. Earlier media/ad-block results remain in [0.3.0](0.3.0.md), and productivity/reminder foundations in [0.4.0](0.4.0.md); those complete suites were not rerun for this visual release.
- The iPhone interface, iCloud sync, Sign in with Apple, EventKit integration and AI agents remain future milestones.
